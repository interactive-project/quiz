# Quiz attempts and engine v1

The ./engine factory implements Protocol EngineSession and loads through the actual Core loader and Registry. It specializes the lifecycle for repeated quiz attempts while using Core's validation, identity, deterministic action/effect and snapshot contracts. It is headless and imports no UI framework. Activity config is the Quiz 1.0.0 learner model; evaluators, validators, clock and UUID generator are live host ports. The practice manifest describes offline local evaluation; secure remote hosts must declare network permissions and offline=false in their selected manifest/catalog, and enforce transport permission at their service boundary.

Actions use interactive-project/quiz.start, answer, clear, navigate, skip, submit, retry, review, hint, timeout, poll, cancel and complete. Every public action is a validated Protocol Action with the current attempt ID and exact next sequence. Sequences and revisions advance once per committed transition and continue across retries. evaluated is a private trusted-result action; public dispatch cannot fabricate it. The host injects unique lowercase UUIDv4 IDs and a nondecreasing epoch-millisecond clock. No random order or implicit timer mutates domain state.

ready -> start -> answering -> submit -> evaluating -> feedback -> review or complete. Answers/navigation/skip are blocked during evaluation and after submission. Double submission is rejected. Retry from feedback/review requires a remaining attempt, creates a new UUID, resets responses/progress/time/hints, changes generation and begins answering. maxAttempts defaults to one and supports up to 100. complete finalizes the activity and prevents retry. A separate start call after retry is invalid because the new attempt already started.

Free navigation permits any question; linear navigation permits the next question only after answering or explicitly skipping the current one. Answer/clear in linear mode targets only the current question. Skip advances without inventing an answer. By default all questions require complete responses before submission; allowUnanswered permits missing ones, graded zero by the evaluator. Matching/fill-blank completeness is checked explicitly.

Optional timeLimitMs is 1 ms through 24 hours measured from the persisted startedAt against the injected clock. At elapsed >= limit answer/navigation/submit are rejected; an explicit timeout action ends the attempt with evaluation.timeout and no score. Hosts decide when to dispatch timeout. Suspension does not pause wall-clock deadlines, and cross-host clocks must use the same trusted time base.

Feedback visibility defaults to after-submit, with after-complete and never alternatives. getFeedback and public state omit the result until permitted. evaluate and serialize are trusted host ports and may contain aggregate scores, never author keys or tests. Hint requests are allowed during answering only for hints=during, or after submission when enabled; repeated requests are rejected. The engine records only question IDs. Hosts serve approved hint content after this gate and must not embed solutions in preallowed hints.

An evaluator receives frozen learner responses, identity, generation and submission revision plus a cancellation signal. Results require exact Protocol identity/revision validation. Native errors and failure messages are sanitized; evidence is excluded from committed public outcomes. The default deadline is 30 seconds, maximum 60 seconds. A pending result remains evaluating and supports explicit poll without a second attempt.submitted event. Cancel commits evaluation.cancelled; late callbacks from canceled/restored/disposed generations are ignored. Trusted completions become a new correlated committed transition; the final evaluate envelope uses its current revision.

Events use the unchanged Events v1 catalog: activity created/started/interacted/resumed/completed/failed, attempt.started/submitted, answer.changed/submitted and hint.requested. Transition events are validated and admission-budgeted before state commits, then delivered after state notification. Payloads carry IDs/revisions and aggregate final outcomes, never raw responses, keys or evaluator service data. Rejected/duplicate actions emit no event. Delivery is bounded in-memory; flushEvents retries the retained outbox before accepting later transitions.

Snapshots bind exact activity content digest, schema version, engine/state version, session and current attempt. State is an allowlisted Quiz stateVersion 1.0.0 including policyKey, progress, next sequence and learner responses. The policyKey prevents restoring under changed attempt/navigation/feedback/time rules. Driver blobs are rejected. Restore validates the whole candidate before atomic commit and rotates generation. A snapshot taken during evaluation restores to canceled feedback; it does not resubmit externally. Resume requires the host to create the engine with the snapshot's validated attempt UUID. Storage/authorization, remote submission idempotency and hint authoring remain host-owned.

Tests cover partial-attempt headless restore, every v1 response-kind snapshot round trip, corrupt response and unsupported-version rejection, attempt limits/new IDs, stale actions, linear navigation, skip/unanswered rules, clock boundaries, hidden feedback/hints, standard event counts/sequences, double submit, evaluation errors, canceled restore, late results, solution/response event isolation and actual Protocol -> Registry -> Core generated-load validation. The host trace is reusable by future DOM/framework adapters; this package does not claim those renderer integrations.
