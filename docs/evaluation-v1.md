# Quiz evaluation and assessment trust v1

Import createLocalEvaluator and createAssessmentEvaluator from ./evaluation. Local practice owns the author document in a private evaluator closure. Secure assessment ships only LearnerQuiz and uses a host-provided remote evaluator; author solutions and trusted tests remain on the trusted server. Do not bundle a local author evaluator into the learner application. The public evaluator/status/result objects never expose solutions. The remote request contains only activity/session/attempt/generation identity, revision and typed learner responses. It does not contain the question document or answer keys. Prompts and assets still require author review because a deliberately embedded key cannot be mechanically removed.

All completed scores use the unchanged Protocol normalized [0,1] envelope with empty evidence by default. Single-choice, true-false, numeric and short-answer are binary. Numeric tolerance is abs(actual-expected) <= max(absolute, relative*abs(expected)); zero expected therefore receives no relative allowance. Units must match exactly. Text comparison uses the declared normalization and accepted author alternatives.

For multiple-choice, matching, fill-blank and ordering, partial credit is clamp((correct - penalty*incorrect)/total,0,1). total is the number of correct selected IDs, left matching items, declared blanks, or ordered items respectively. Missing selections/pairs/blanks contribute zero; incorrect submitted ones are penalized. Ordering counts correct positions. penalty defaults to 1 and may range from 0 to 1. When partialCredit is false, full correctness is required. This explicitly forbids negative grades and duplicate submission credit.

Aggregation is sum(weight*question score)/sum(weight), in declared question order. Weights default to 1, may be 0 through 1,000,000, and at least one question must have positive weight. The host-owned separate scoring policy may declare scoringVersion 1.0.0; it does not modify Quiz v1 question models. Unanswered questions score zero. Structurally or semantically ungradable responses, wrong units, duplicate question responses and unknown IDs produce a failed evaluation with no score, distinct from a valid wrong answer.

Local evaluation is pure and repeatable for identical captured author/scoring data and input. Remote results must pass the host's Protocol validator, exact identity/attempt/revision binding and normalized score bounds. Secure calls additionally require a generation UUID matching getCurrent, preventing completion after restore to the same revision. Native service failures and remote failure messages are replaced by static messages; error, timeout and cancellation use Protocol evaluation.failure, evaluation.timeout and evaluation.cancelled. Result evidence metadata from a trusted server must be authorized by that server and host policy.

Assessment status is idle/pending/completed/failed/disposed with at most one active operation. While waiting, getStatus exposes a Protocol pending result without response content. A remote pending result remains pending for an explicit later evaluation. Superseding a different frame cancels the old operation; late callbacks cannot replace the newer status. Identical in-flight calls share a promise, owned by the first caller's cancellation signal. The default deadline is 30 seconds, configurable up to 60 seconds. Cancellation is cooperative for host services; the boundary stops accepting a late result regardless of cleanup.

No answer key, trusted tests, credentials or live service handle belongs in Core domain state, events or snapshots. Use only learner responses/progress as domain state, inject evaluator services privately, and publish only the validated aggregate result. Server submission authorization, replay protection and durable idempotency are host responsibilities; a remote result is not trusted merely because it has a valid schema. This library does not create a server or network transport. Core#3 effect/evaluation semantics and Core#4 generation rotation compose with this boundary; the v1 Quiz engine wires these contracts through a trusted injected evaluator. See [interop-v1](interop-v1.md) for generated-data gates and host-specific permission requirements.

Tests exercise all eight grading types, score bounds, weights, partial credit, penalty extremes, numeric zero/tolerance limits, unanswered and duplicate responses, repeated evaluation, equivalent local/remote envelopes, hidden-key projection/request/status isolation, foreign/invalid remote results, pending, cancellation, timeout and restored-generation rejection.
